# Jev 与 Vercel AI Gateway

本项目使用现有的 npm 工具链安装 `ai`，通过 AI SDK 的
`experimental_evaluate` 调用 `typesafe-ai/jev`。

Jev 返回结构化判断和概率，不支持 `generateText` 自由生成文字。验证脚本
输出的中文句子是代码根据真实判断格式化的结果，不是模型生成的回答。

## 本地配置

需要 Node.js 22.18 或更新版本。在项目根目录执行：

```bash
npm install
npm run gateway:setup
npm run gateway:verify
```

配置脚本通过本地终端隐藏输入密钥，写入 `.env.local` 的
`AI_GATEWAY_API_KEY`。该文件已被 Git 忽略，写入权限为 `600`。
macOS 也可运行 `python3 scripts/setup-ai-gateway-key.py --dialog`，使用隐藏输入框。
不要把密钥写入命令参数、聊天、代码或日志。

验证脚本使用 SDK 自动读取的环境变量认证，密钥只在 Node 进程中用于请求。
本地环境文件按项目路径加载，不依赖启动命令的工作目录。

## 调用约束

- 模型 ID：`typesafe-ai/jev`。
- 上下文按 32K 预算控制；脚本用请求 JSON 的 UTF-8 字节数作保守估算，
  另预留 2048 预算用于协议开销。这不是模型 tokenizer 的精确计数。
- 超预算时拒绝请求，不静默截断源字幕。
- 每次请求最长 45 秒，临时故障最多重试一次。
- 错误仅输出白名单原因或 HTTP 状态，不序列化 SDK 异常或请求头。
- `experimental_evaluate` 仍是实验接口，因此固定 SDK 版本并保留 npm 锁文件。

## 字幕语义复核

项目默认 YAML 和桌面端新生成的配置已启用：

```yaml
pipeline:
  semantic_quality: "jev"
```

显式改为 `"off"` 可关闭。旧的自定义 YAML 未包含此项时保持关闭；已有翻译任务
恢复时仍采用当时的配置快照，启用新能力应创建新的翻译任务。

Python 流水线通过 `scripts/jev-evaluate.mjs` 使用 AI SDK。Node 必须可从 `PATH`
找到，也可通过 `SUBTITLE_LLM_NODE` 指定 Node 可执行文件的绝对路径。
纯 Python 安装而没有本仓库的 Node 依赖时，不能完成 Jev 检查。

质检以翻译流水线的完整 chunk 为证据单位。每次请求都包含：

- 当前 chunk 的全部原文和最新译文，保持字幕顺序。
- 任务生成的完整摘要、术语与原文纠错背景。
- 当前片段编号、总片段数、时间范围、源语言、输入来源（ASR 或字幕）。
- 翻译规划中的只读边界上下文；模型断句模式还共享翻译提示使用的前后各 24 个源文位置。
- 明确的复核任务说明：当前已完成翻译，正在检查实质含义问题，不生成或改写字幕。
  要联合阅读原文及译文的跨条承接，考虑识别文本的标点、断词与专名歧义，区分翻译错误与措辞偏好。

每个 chunk 只提交一次，共 8 个问题：四类缺陷各用一个 Boolean 判断整段是否存在问题，
再用一个 Choice 对该 chunk 的行号候选排序。原文与译文只放在共享状态中，行号候选描述为 null，
不再为每条字幕展开四段提问。

四类判断仍为：语义关系改变、重要信息遗漏、无依据增译、术语或实体误译。

### 概率与定位

- **整段存在概率**低于 0.4 不产生该类候选；0.4～0.9 标记判断不确定，≥0.9 表示整段高度疑似存在问题。
- **行号排名份额**加起来为 1，只反映候选之间的相对排序，不是该行出错的概率，不能套用 0.4 阈值。
- 每个达到复核阈值的类别最多取排名前三个非零候选，保留模型选中的并列第一项。
  候选均作为低严重度的定位提示，不宣称这些行已经确认出错，也不保证穷尽该类别的全部问题。
- 完整行号分布保存在报告的 `judgments` 中。即使排名很集中，只要整段存在概率低于阈值，也不标记该行。
- 这些是试运行规则，尚未用完整人工标注校准整段阈值和候选数量。

Jev 候选不单独触发自动重译：自动模式保留译文和警告状态，TUI 模式进入已有复核流程。
规则检查发现的缺失、格式等问题仍沿用原有修复流程。

### 预算与缓存

当前保留 29,952 字节的保守请求预算，以及 Choice 每题最多 255 个候选的限制。
完整请求超限时明确记录未检查，不裁剪上下文、丢弃行号或重新展开逐行问题。
空译文交由确定性规则处理，不列入 Choice 候选，但仍保留在完整上下文中；全空片段不请求 Jev。

相同原文、译文、上下文、目标语言和问题版本复用任务 SQLite 中的判断；证据变化后重新检查。
完整 chunk 中远处的译文或边界上下文变化，也会使该 chunk 的旧判断失效。
当前问题版本为 **3**，不会复用版本 1、2 的逐行判断。

缓存保存实际请求、原始回答、舍入精度和用量；报告每个 chunk 记录四类 `judgments`：
`exists_probability`、`selected_line`、`line_probabilities`。候选 issue 的指标分别命名为
`chunk_probability`、`location_score`、`location_rank`，不使用含义模糊的逐行 `probability`。
报告中的 `cue_ids` 表示这次整段检查所包含的字幕，不代表对每一行做了独立二元判断。

已完成的内存缓存复查不获取网络锁，TUI 接受同一份证据不会等待其他片段的联网检查。
同一请求的失败记录在本任务内也只追加一次，避免多次诊断重复记录。
服务故障仍沿用停止本任务后续新请求的策略；已成功缓存的判断继续可用。服务失败恢复策略未在本次重做。
恢复已经接受的片段沿用原接受记录，不强制重新付费检查。
